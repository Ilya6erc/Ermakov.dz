Теоретическая часть:
• Перечислите основные преимущества использования Git:
1. git init - Создаёт новый репозиторий в текущей папке
2. cd | - Переносит в указанную папку
3. git commit -m "текст" - Создаёт коммит с комментарием
4. git config --global user.name "Имя" - Устанавливает имя для коммитов
5. git config --global user.email "почта" - Устанавливает email для коммитов
6. git add . - добавляет все файлы в commit
7. git branch -M main - Переключение между ветками
8. git remote add origin <ссылка> - Связывает локальный репозиторий с удалённым
9. git push -u origin main - Отправляет изменения на GitHub

• Опишите, какие проблемы решает Git при командной разработке:
1. Конфликты при одновременной работе
2. Потеря истории изменений
3. Страх сломать рабочий код
4. Синхронизация между устройствами
5. Совместная работа без хаоса

• Объясните разницу между локальным и удалённым репозиторием.
1. Локальный репозиторий — это папка на твоём компьютере, в которой Git отслеживает изменения.
Он создаётся командой git init или git clone.
2.Удалённый репозиторий — это копия проекта на сервере.
Он нужен для совместной работы и резервного копирования.
Ты отправляешь туда свои изменения командой git push и скачиваешь чужие командой git pull или git fetch.

Аналитическая часть:

Если не настроить user.name и user.email, возникают три основных проблемы.

1. Коммиты не создаются вообще
2. Авторство коммитов теряется или путается
3. Проблемы с GitHub и правами доступа

Объясните, почему важно писать осмысленные комментарии к коммитам:

1. Понять историю изменений - Через месяц ты не вспомнишь, что делал вчера. Комментарий типа «fix bug» бесполезен —
непонятно, какой баг и где. А «Fix crash when opening settings on Android» сразу объясняет суть.
2. Быстро найти нужное изменение = Когда нужно откатить конкретную правку, осмысленные комментарии позволяют найти её за
секунды через git log. Без них придётся перебирать все коммиты подряд и смотреть код.
3. Помочь комманде - В командной работе комментарии — это способ общения.
4. Автоматизация и релизы - Многие инструменты (CI/CD, генераторы changelog) читают комментарии коммитов
и строят на их основе список изменений для релиза.
5. Профессионализм - Аккуратные коммиты — признак зрелого разработчика.

Представьте ситуацию: вы случайно удалили важный файл в репозитории. Как
Git может помочь восстановить его?
Ответ:
Это самый простой случай. Ты просто удалил файл из папки, но Git еще «помнит» его в последнем
коммите. Восстановить можно одной командой:
git restore — команда, которая вернет файлы в состояние из последнего коммита.
Она отменяет твои локальные изменения.
Если удалил README.md То так: git restore README.md
